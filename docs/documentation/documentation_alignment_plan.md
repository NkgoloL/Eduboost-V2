# EduBoost Documentation Alignment Plan

## Purpose

Bring active EduBoost documentation into agreement with the implementation and with one another. The work must preserve historical evidence, keep release and live-traffic boundaries fail-closed, and prevent future documentation drift through generated artifacts and semantic checks.

This plan is based on the true-state audit performed on 2026-09-03 against `master` commit `06fbf1816` in the Development checkout. The dedicated working branch is `docs/documentation-alignment`, created from that commit. The reported `AssessmentType` fix at feature-branch commit `7e635184` is not part of this branch baseline and must not be treated as verified here until it is merged or independently checked out.

## Non-negotiable rules

1. No document may authorize production release, deployment, public beta, billing, live payment processing, live learner traffic, or a new KG slice unless the authoritative register explicitly changes that boundary.
2. Historical evidence remains available, but must be clearly marked historical, archived, generated, evidence, draft, or superseded.
3. Machine-readable authority is reconciled before prose is rewritten.
4. Generated files are regenerated by their owning scripts; they are not hand-edited.
5. Every current implementation claim must have a code anchor and an executable evidence command.
6. Changes are delivered in small reviewable slices, with a clean validation gate after each slice.

## Authority model to establish

### A. Runtime facts

Source these from executable code and generated artifacts:

- Backend entrypoint and route inventory: `app/api_v2.py`, `scripts/check_runtime_entrypoints.py`, `scripts/generate_route_inventory.py`.
- Frontend versions and commands: `app/frontend/package.json`, `app/frontend/pnpm-lock.yaml`.

- Persistence: Alembic graph, models, and schema-integrity checks.
- Deployment topology: authoritative deployment contract plus the selected IaC/configuration.

### B. Governance and release authority

Canonical active release-readiness register: `docs/roadmap/production_readiness/prd11_production_release_register.json` (see Workstream 1, task 1). The other registers below are scoped supporting records and must not independently define the active PRD authority.

Select exactly one canonical readiness state object. Reconcile:

- `docs/roadmap/production_readiness/production_readiness_register.json`
- `docs/roadmap/production_readiness/prd11_production_release_register.json`
- `docs/roadmap/production_readiness/true_state_remediation_register.json`
- Relevant PRD/true-state evidence records

Derived summaries must be generated from this authority rather than independently edited.

### C. Documentation classification

Every document in the inventory receives one disposition:

- `keep_current`: active and aligned
- `rewrite`: active but factually or semantically stale
- `merge`: duplicate of a canonical document
- `archive`: historical or superseded
- `generated`: regenerated from code/register state
- `evidence`: immutable proof linked from a current summary

## Risks and safeguards

| Risk | Safeguard |
|---|---|
| Register cleanup accidentally authorizes release | Assert all protected booleans remain false before and after changes. |
| Generated evidence is overwritten during verification | Run checks in a disposable copy where possible; inspect `git status` after every evidence command. |
| Historical documents are deleted before traceability is preserved | Classify/archive first; delete only with an approved migration manifest. |
| Large documentation rewrite hides factual changes | Use domain-sized commits and require diff review against code anchors. |
| Deployment target choice remains ambiguous | Block deployment-doc closure until target and topology are explicitly decided. |
| Local environment masks CI failures | Record interpreter/tool versions and run the canonical commands from a clean dependency-complete environment. |
| Stale terminology is incorrectly removed | Review each stale-term finding before updating its ratchet baseline. |
