# EduBoost V2: Pilot Stop & Rollback Criteria

**Control ID**: `TSR-12.6`  
**Release Gate**: `RG-5`  
**Status**: Authoritative  
**Domain**: Operations / Resiliency / Incident Management  

---

## 1. Objective & Non-Negotiable Boundaries

The EduBoost V2 pilot operates under strict **fail-closed** governance. This document defines the exact conditions under which the pilot must be stopped immediately and the procedures for rolling back application state, data, and access.

---

## 2. Hard Stop Criteria (Tripwires)

If any of the following conditions occur, the system triggers an immediate **Hard Stop**:

| Category | Tripwire Condition | Immediate Automated / Manual Action |
| :--- | :--- | :--- |
| **Privacy / POPIA** | Any unencrypted learner PII detected in external logs, or failed DSR deletion cascade. | Pilot kill-switch engaged (`PILOT_ACTIVE=false`); learner session tokens invalidated. |
| **Security** | Cross-tenant learner data leakage or privilege escalation vulnerability exploited. | Application traffic diverted to maintenance page; DB transactions halted. |
| **Safety / Harm** | Inappropriate or unaligned content generated by LLM tutor that passes output filters. | LLM pipeline instantly disabled (`LLM_ENABLED=false`); fallback to static item bank. |
| **Financial** | AI token spend or infrastructure cost exceeding 150% of allocated daily budget. | AI API keys rotated / calls suspended by `AIBudgetGuard`. |
| **Data Loss / Drift** | Database schema corruption, replication lag $> 60\text{s}$, or failed audit ledger validation. | Read-only mode activated; database restore protocol initiated. |

---

## 3. Rollback Playbook & Execution Sequence

When a hard stop or critical defect requires a rollback:

### Phase 1: Traffic & Session Drain (T + 0 min)
```bash
# 1. Engage immediate pilot maintenance lock
export PILOT_ACTIVE=false
export MAINTENANCE_MODE=true

# 2. Invalidate all active JWT tokens
python3 -m scripts.security.revoke_all_sessions --cohort pilot-2026
```

### Phase 2: Application Container Reversion (T + 5 min)
```bash
# Revert Docker deployment to the previous verified stable tag
docker compose -f docker-compose.prod.yml down
docker compose -f docker-compose.prod.yml up -d --build eduboost-api:v2-previous-stable
```

### Phase 3: Database State Recovery (if schema or data corruption occurred)
```bash
# 1. Verify last known clean snapshot from S3/backup storage
python3 -m scripts.maintenance.verify_backup_integrity --latest

# 2. Execute transactional restoration using verified drill procedure
python3 -m scripts.maintenance.restore_db_snapshot --snapshot-id <clean-snapshot-sha>
```

### Phase 4: Incident Post-Mortem & Custody Logging
- Compile telemetry logs into `docs/release-evidence/incidents/`.
- Issue an Incident & Rollback Record signed by the Lead Maintainer.
- The pilot may not resume without formal Root Cause Analysis (RCA) and updated regression tests.
